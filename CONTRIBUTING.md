# Contributing to Cairn

Cairn is a single-page app with no server. All data lives in the browser's `localStorage`, and a fresh visit starts from the demo workspace in `src/domain/seed.ts`. This guide covers how to run the project, where code lives, and the conventions a change has to follow to pass review.

## Set up

You need Node.js 22 or newer (`.nvmrc` pins 22).

```sh
pnpm install
pnpm exec playwright install chromium  # once, for the end-to-end specs
pnpm run dev                          # http://localhost:5174
```

To start over with the demo data, open **Help & resources** in the sidebar and choose **Reset demo data**. The same menu has **Simulate offline**, which makes every data change fail with a retry toast.

In development, `window.__cairn` holds the store and the router for debugging from the browser console. Production builds leave it out.

## Scripts

| Script                  | What it does                                                           |
| ----------------------- | ---------------------------------------------------------------------- |
| `pnpm run dev`          | Starts the Vite dev server on port 5174.                               |
| `pnpm run build`        | Builds the production bundle into `dist/`.                             |
| `pnpm run preview`      | Serves `dist/` on port 5174.                                           |
| `pnpm run typecheck`    | Runs `tsc` over `src`, `e2e` and the config files.                     |
| `pnpm run lint`         | Runs ESLint.                                                           |
| `pnpm run format`       | Formats every file with Prettier.                                      |
| `pnpm run format:check` | Fails if a file is not formatted.                                      |
| `pnpm run test`         | Runs the Vitest unit tests (`src/**/*.test.ts`).                       |
| `pnpm run e2e`          | Runs the Playwright specs in `e2e/` against a dev server on port 5180. |

CI runs all of these on every pull request. Before you open one, run:

```sh
pnpm run typecheck && pnpm run lint && pnpm run format:check && pnpm run test && pnpm run e2e
```

## Stack

- React 19 with the React Compiler, TypeScript, and Vite.
- TanStack Router with file-based routes, split per route.
- zustand with immer for state, and zod schemas for everything persisted.
- shadcn components on Base UI, styled with Tailwind CSS v4. `src/index.css` is the only stylesheet.
- lucide-react for icons, `@dnd-kit` for drag and drop, cmdk for the command palette, and Sonner for toasts.
- Vitest for unit tests and Playwright for end-to-end specs.

## Where code lives

```
src/
  main.tsx            entry: applies preferences, binds the router to the store, renders the app
  router.tsx          the TanStack router
  routes/             one file per URL; each renders a page component. Do not edit routeTree.gen.ts, the router plugin writes it.
  index.css           Tailwind setup and the Cairn theme: tokens, light and dark values, accents, density, motion
  domain/             data with no React: constants, dates, branded ids, zod schemas, the seed workspace
  store/              the zustand store, selectors, actions, navigation, and the transient UI state types
  shell/              the app frame (sidebar, topbar, mobile nav), shell menus, error pages, skeletons, document theming
  components/ui/      shadcn components generated by the shadcn CLI
  components/         shared app components: the task list, pickers, task and project menus, view grouping
  ui/                 small render helpers (Avatar, StatusIcon, Empty, FilePreview, Tip), the brand, data-named icons, toast()
  overlays/           the task drawer, every modal, the command palette, and the global keyboard shortcuts
  project/            the project page and its views: board, list, table, calendar, timeline, files, overview
  pages/              workspace pages (Home, Inbox, My Tasks, Members, Teams, …) and page building blocks in kit.tsx
  settings/           the Settings sections
  auth/               sign in, sign up, password reset, verification, and onboarding
e2e/
  fixtures.ts         the `test` and `expect` every spec imports
  app/                app-wide behaviour: navigation, every route, storage, theme, pickers, task menu
  views/              the project views
  overlays/           the drawer, modals, palette, comments, subtasks, shortcuts
  pages/              workspace pages, settings, auth and onboarding
```

Import shadcn components and `cn` through the `@/` alias (`@/components/ui/button`, `@/lib/utils`). Use relative imports for everything else.

### Add a page

1. Write the page component in `src/pages/` (or the folder it belongs to).
2. Add a route file under `src/routes/_app/` that renders it. Routes under `_app` render inside the shell. The dev server regenerates `src/routeTree.gen.ts`, so commit that file with your change.
3. Add the route to `PAGE_ROUTES` and `PAGE_PATHS` in `src/store/nav.ts`, and its name to `ROUTE_NAMES` in `src/shell/shell.tsx` for the breadcrumb and the document title.
4. Add the path to `e2e/app/routes.spec.ts`. That spec loads every route and fails on any console error.

## Styling

Style with Tailwind utilities on shadcn components. Do not add CSS files. `src/index.css` is the only stylesheet, and it holds the theme.

- Use theme tokens for every colour. Tailwind's default palette is removed (`--color-*: initial`), so `text-red-500` does not exist. Do not write hex, `rgb()`, or `oklch()` colours in `src`.
- A colour that comes from data (a project's, member's, or label's colour) goes in the `--c` custom property. Read it with `bg-(--c)`, `bg-(--c)/16`, `text-(--c)`, `text-tint`, or `avatar-tint`.
- Combine classes with `cn()` from `@/lib/utils`: `cn('h-8 px-2', on && 'bg-muted')`.
- Use `cva` only for a reusable component with real variants, like `buttonVariants`. A one-off condition is `cn()`.
- Prettier sorts the classes in `className`, `cn()` and `cva()` (`prettier-plugin-tailwindcss`). Run `pnpm run format` instead of ordering them by hand.

### Theme tokens

| Token (Tailwind name)                                               | Use                                                   |
| ------------------------------------------------------------------- | ----------------------------------------------------- |
| `background`, `card`, `popover`                                     | the main area, cards, menus                           |
| `foreground`                                                        | body text                                             |
| `fg-2`                                                              | secondary text                                        |
| `muted-foreground`                                                  | meta text, placeholders, group labels                 |
| `fg-4`                                                              | faint icons                                           |
| `muted`, `accent`, `secondary`                                      | hover fills, subtle panels                            |
| `muted-strong`                                                      | segmented controls, progress tracks, skeletons        |
| `sunken`, `canvas`                                                  | inset inputs; the page behind auth cards              |
| `border`, `input`, `divider`                                        | lines; control borders; row separators                |
| `primary`, `primary-foreground`                                     | the brand accent, which follows Settings > Appearance |
| `primary-soft`, `primary-line`                                      | selected rows, chips                                  |
| `ring`                                                              | focus rings                                           |
| `destructive`                                                       | errors and destructive actions                        |
| `green` `amber` `red` `blue` `violet` `teal` `rose` `orange` `gray` | semantic and label hues                               |
| `status-backlog` to `status-done`                                   | status colours                                        |
| `sidebar*`, `overlay`                                               | the shell, and the scrim behind dialogs               |

`primary` is the brand accent. shadcn's `accent` is a neutral hover fill, not the brand colour.

The type scale is `text-2xs` (11px), `text-xs` (12px), `text-sm` (12.5px, controls), `text-base` (13.5px, body, rows and menus), `text-md` (14.5px), `text-lg` (16px), `text-xl` (19px), and `text-2xl` (23px).

The radii are `rounded-sm` (4px), `rounded-md` (6px, controls), `rounded-lg` (8px), and `rounded-xl` (10px, cards, menus and dialogs). The shadows are `shadow-xs` (outline buttons), `shadow-card` (cards), `shadow-md` (menus and toasts), and `shadow-drag` (a dragged card).

Density follows Settings. Use `h-(--row-h)` for list and table rows, `p-(--card-pad)` for board cards, and `px-(--gutter)` for the content edge (24px, or 16px below `md`). For a standard page column, use `Page` from `src/pages/kit.tsx` instead of repeating its classes.

### Breakpoints

- `md` is 900px. Below it, the sidebar becomes a sheet.
- `sm` is 640px. Below it, the bottom nav appears. Hide secondary columns on phones with `max-sm:hidden`.
- The topbar search collapses at `max-[1100px]:`.

## shadcn and Base UI

`src/components/ui/` holds shadcn components generated by the shadcn CLI on Base UI (`components.json`). To add one, run `pnpm dlx shadcn@latest add <name>`. Do not copy components by hand.

Customise a component where you use it, with `className`. Change the generated file only for a change the whole app needs, and mark it with a `// Cairn:` comment so the change survives a regenerate.

Base UI composes through `render`, not `asChild`:

```tsx
<DropdownMenuTrigger render={<Button variant="ghost" size="icon-sm" aria-label="More actions" />}>
  <Ellipsis />
</DropdownMenuTrigger>
```

A Base UI `Button` rendered as a link needs `nativeButton={false}`.

### Icons

Import lucide icons directly (`import { Plus } from 'lucide-react'`) and size them with `size-*`. Buttons and menu items size their icons for you.

Use `<Icon name="…" />` from `src/ui/icon.tsx` only when the icon name is data: a project's or team's stored icon, file types, project tabs, templates, and filter fields. Its map keys are the stored names.

lucide 1.x renamed some icons. `Trash2` is `Trash`, `CircleAlert` is `CircleExclamationPoint`, `CircleHelp` is `CircleQuestionMark`, and `Building2` is `BuildingComplex`.

### Clickable rows and cards

Never nest a button in a button, and never put `onClick` on a `div`. Make the title a `<button>` or `<a>` with `after:absolute after:inset-0` inside a `relative` container, and give the controls inside it `relative z-10`. `MiniRow` and the task list's title cell show the pattern.

For a link to an app route, spread `linkTo(target)` from `src/shell/shell.tsx` on an `<a>`. It gives the link a real `href`, so opening it in a new tab works, and navigates in the app on a plain click.

## State

The app has one zustand store, `useStore`, exported from `src/store`. It has four slices:

- `data` holds the persisted entities, parsed by the zod schemas in `src/domain/schema.ts`.
- `prefs` holds the user's preferences.
- `views` holds each view's filters, sort and grouping, keyed by `ViewKey`.
- `ui` holds transient state. Its types are in `src/store/ui.ts`.

The store persists to `localStorage` under `gr8r.v2`, a key that predates the Cairn name and stays so older saves still load. That shape is shared with saves from the original JavaScript version of the app, and `e2e/app/storage.spec.ts` checks that such a save still loads. Keep new fields optional, with defaults in the schema.

### Read state

Select stored values only: `useStore(s => s.data)` or `useStore(s => projectById(s.data, id))`. A selector that builds a new object or array, like `s => s.data.tasks.filter(…)`, re-renders forever. Derive in render with the selectors in `src/store/selectors.ts` instead (`allTasks`, `tasksOf`, `visibleProjects`, `canSee`, `isOver`, `progressOf`, `applyView`, `sortTasks`, `searchAll`).

Read a view with `useView(key)`.

### Change state

- Change data through `mutate(s => { … })`. It refuses the change and returns false while the app is offline. Inside it, record the change with `logAct`, and use `applyPatch`, `createTask`, `deleteTasks`, or `createProject` where they fit.
- Change UI-only state with `set(s => { … })`, or `setUi(key, value)` for page tabs and segmented controls.
- Change a view with `updateView(key, v => { … })`.

`mutate` and `set` both pass an immer draft. Open and closed state of a popover or menu does not go in the store. It lives in the component, next to its trigger.

To offer undo, take a snapshot before the change and restore it from the toast, as `archiveTask` does:

```ts
const snap = snapshot();
if (mutate(s => { … })) toast('Task archived', { action: 'Undo', onAction: () => restore(snap) });
```

`toast(msg, { kind, action, onAction, ms })` from `src/ui/toast.tsx` renders through the Sonner `<Toaster />` in the root route.

Ids are branded types (`TaskId`, `ProjectId`, and so on). Brand a literal or a URL value with the helpers in `src/domain/ids.ts`, such as `taskId('t3')`.

Preferences reach the page through `applyPrefs` in `src/shell/document.ts`. It sets `.dark`, `data-accent`, `data-side`, `data-density`, and `data-motion` on `<html>`. Change preferences through the store, and never set these attributes yourself.

### Actions

`src/store/actions.ts` holds the actions the whole app shares: tasks (`openTask`, `newTask`, `updateTask`, `toggleDone`, `archiveTask`, `delTask`), projects (`newProject`, `archiveProject`, `moveProject`), views (`sortBy`, `rmFilter`, `clearFilters`), overlays (`openModal`, `closeModal`, `confirm`, `prompt`, `openPalette`), and workspace actions. Navigate with `go({ r: 'project', id, tab })` and `back()` from `src/store/nav.ts`, and read the current route with `useRoute()`.

`confirm` and `prompt` return promises:

```ts
if (await confirm({ title: 'Delete project?', body: 'This cannot be undone.', ok: 'Delete', danger: true })) run();
const name = await prompt({ title: 'Rename view', label: 'Name', value: v.name }); // null when dismissed
```

Actions that only one area needs live next to it, for example `src/project/actions.ts` for the project views.

## Popovers, menus and pickers

Each popover, menu and picker wraps its trigger, owns its open state, anchors to the trigger, and returns focus to it when it closes. Pass the trigger as the only child. It must be a single element that forwards props, such as a `<button>` or a shadcn `Button`.

The shared pickers in `src/components/pickers` take `value`, `onChange`, and the trigger:

```tsx
<StatusPicker value={t.status} onChange={status => updateTask(t.id, { status })}>
  <button className={pill} aria-label={`Status: ${ST[t.status].name}`}>
    <StatusPill st={t.status} />
  </button>
</StatusPicker>
```

- `StatusPicker`, `PriorityPicker`, `EstimatePicker` and `RecurPicker` are menus of radio items. Number keys 1 to 5 pick a status.
- `AssigneePicker` and `ProjectPicker` are searchable single pickers. `LabelsPicker` and `DepsPicker` pick several values and stay open.
- `DatePicker` has quick picks and a month grid. `onChange(null)` clears the date.
- For the task form, pass the form's value and call `updateTask('form', patch)`.

Build any other picker on `MenuPicker` (a short fixed list) or `ComboPicker` (searchable, optionally `multiple`). `PickerRadioItems` with the exported option lists fills a context-menu submenu.

For the task's "…" button, use `<TaskMenu id={t.id}>`. For right click on a row or card, wrap it in `<TaskContextMenu id={t.id}>`. Both show the same items. `ProjectMenu` and `ProjectContextMenu` in `src/components/project-menu.tsx` do the same for projects.

## The overlay host

The task drawer, the modals, and the command palette can open from anywhere: shortcuts, the palette, or a menu. Their state is central, in `ui.drawer`, `ui.modals`, and `ui.palette`. `Layer` in `src/overlays/layer.tsx` renders them once, from the root route, and installs the global keyboard shortcuts.

- The drawer is a shadcn `Sheet`. As a side panel it has no scrim and leaves the page usable. In full-page mode it is modal.
- Each modal is a `Dialog`, and later modals stack on top. A `confirm` modal is an `AlertDialog`.
- The palette is a `CommandDialog`.

To add a modal, add its type to the `Modal` union in `src/store/ui.ts`, render it in `ModalBody` in `src/overlays/modals.tsx`, and open it with `openModal({ type, … })`.

## Drag and drop

The board, the timeline, and the subtask checklist use `@dnd-kit`. List rows and sidebar projects use native drag and drop, handled once for the whole document in `src/project/row-dnd.ts`. Those elements carry data attributes the handlers read: `data-task-row`, `data-drag-row` (on the handle), `data-group`, `data-lkey` and `data-grp-drop` on list rows, and `data-drag-proj` and `data-proj-drop` on sidebar projects. Keep these attributes when you change that markup. Alt+Arrow Up and Down move the focused list row.

## Accessibility

- Every action works from the keyboard. Menus, pickers and dialogs return focus to their trigger when they close. Base UI handles this when the trigger is a real element.
- shadcn components draw a focus ring on `:focus-visible`, and the theme gives every other focused element a 2px `ring` outline. Do not remove outlines.
- Give icon-only buttons an `aria-label`. Name fields with a `<label>` or `aria-label`.
- Every page has an `h1`. Use a visually hidden one (`sr-only`) if the design shows no title.

## Motion

- Anything pressable scales to `active:scale-97`. The shadcn `Button` already does.
- Popovers and menus scale from their trigger with `origin-(--transform-origin)`. Never set the origin to the centre on an anchored surface. Modals and sheets stay centred or edge-anchored.
- Enter with the theme's ease-out, `cubic-bezier(0.23, 1, 0.32, 1)`. `ease-out`, the default transition curve, and tw-animate-css's `animate-in` and `animate-out` all use it. Keep durations between `duration-150` and `duration-250`. Never animate from scale 0: use `zoom-in-95`, not `zoom-in`.
- Surfaces opened from the keyboard many times a day open without animation. The command palette passes `instant` to `DialogContent`.
- The theme redefines `hover:` (and so `group-hover:`) to apply only on devices with a fine pointer. Write `hover:` as usual.
- Reduced motion follows the OS setting and Settings > Appearance > Motion (`data-motion` on `<html>`). The theme removes movement from every tw-animate animation, keeps fades, and makes transitions instant. `motion-reduce:` and `motion-safe:` follow the app setting too.
- One-shot effects use the `ui.fx` flags (`added`, `done`, `moved`, `route`, `tab`), which expire on their own. `fxEnter(fx, id)` from `src/components/task-list.tsx` is the row entrance.

## Tests

### End-to-end specs

Add a spec for every interaction you add or change, in the `e2e/` folder that matches the area.

- Import `test` and `expect` from `e2e/fixtures.ts`, not from `@playwright/test`. The fixture freezes the clock at Wednesday, 7 October 2026, 2:30 pm in Los Angeles, clears storage once per test (a reload keeps what the test saved), and fails the test on any console error or uncaught exception.
- Query by role and accessible name, such as `page.getByRole('button', { name: 'Status: Backlog' })`. Never query by class.
- Assert what the user sees. If the change persists, reload the page and assert again.

```ts
import { expect, test } from '../fixtures';

test('the status picker changes a task, and the change persists', async ({ page }) => {
  await page.goto('/projects/p1/list');
  const row = page.getByRole('row').filter({ hasText: 'Write homepage copy' });
  await row.getByRole('button', { name: 'Status: Backlog' }).click();
  await page.getByRole('menuitemradio', { name: 'In Progress' }).click();
  await expect(row.getByRole('button', { name: 'Status: In Progress' })).toBeVisible();

  await page.reload();
  await expect(row.getByRole('button', { name: 'Status: In Progress' })).toBeVisible();
});
```

`pnpm run e2e` starts its own dev server on port 5180. To run against a dev server you already have, set `E2E_URL`:

```sh
E2E_URL=http://localhost:5174 pnpm exec playwright test e2e/views
```

### Unit tests

Put unit tests next to the code as `*.test.ts`. They suit pure logic, such as the store's persistence and the navigation mapping in `src/store/`.
